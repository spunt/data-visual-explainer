Now the general rule, one step at a time. Each step has the plain version, with the exact version one click away.

  1. Step 1 · Who is counted

    Start with users, then apply each rule

    One PixelPress account that started a mobile PixelPress Pro trial.

    Exactly

    One DISTINCT t.user_id from app.trial_events after grouping all PIXELPRESS_PRO iOS or Android trial events to that user's MIN(trial_start_date).

    S3

  2. Step 2 · When the clock starts

    Time zero: trial start

    Each user's clock starts on the date their first qualifying mobile trial began.

    • Implemented charge window: Trial day 0 through day 14, counting the date as day 0. (days 0–14)
    Exactly

    trial_start_date = MIN(t.trial_start_date) over PIXELPRESS_PRO iOS or Android trial events for that user_id.

    S3

  3. Step 3 · What counts

    Converted to paid

    Counts a user if they had at least one positive first charge inside the implemented charge window.

    Exactly

    first_charge groups the cohort by user_id and keeps MIN(b.charge_date) where billing.charges.amount_usd > 0 and the charge_date falls in the implemented charge window. The final SELECT counts DISTINCT f.user_id.

    S3

  4. Step 4 · Combine

    Turn yes/no answers into a share

    Divide users with a qualifying charge by all users in the implemented trial cohort.

    Exactly

    ROUND(100.0 * COUNT(DISTINCT f.user_id) / COUNT(DISTINCT c.user_id), 2) AS conversion_rate_pct after LEFT JOIN first_charge f ON f.user_id = c.user_id.

Judgment calls

Which number to document

Chose: Use the 14.3% headline from the readout and saved conversion_summary.csv, but define it by the SQL that produced the CSV.

Could have chosen: Rewrite the card around the README's 30-day definition or the readout's 1.4-point lift.

Why: The skill requires tracing the headline number to code and recording disagreements.

What it changes: The card is a descriptive card for the implemented March conversion rate, not a causal card for onboarding.

How to represent the inclusive SQL window

Chose: Model the outcome window as offsets 0 through 14, using an exclusive-end card window of 15 days.

Could have chosen: Label it "14 days" from the parameter name alone.

Why: SQL BETWEEN includes both trial_start_date and DATE_ADD(trial_start_date, 14).

What it changes: Readers can see the boundary case: a charge on day 14 counts, while day 15 does not.

Where the description and the code disagree

Conversion window

Described

README and readout define conversion as paying within 30 days of trial start.

Implemented

SQL sets conversion_days = 14 and uses charge_date BETWEEN trial_start_date and DATE_ADD(trial_start_date, 14), inclusive.

Impact: The implemented metric likely understates a true 30-day conversion rate. The size is unknown from the supplied output.

Cohort end date

Described

README says trials started 2026-03-02 through 2026-03-08.

Implemented

SQL sets cohort_end = DATE '2026-03-09' and uses BETWEEN, so 9 March is included.

Impact: Adds one extra start date relative to the README. Direction and size are unknown because no daily breakdown is supplied.

S1S3

Internal and test account exclusions

Described

README says internal and test accounts are excluded.

Implemented

The supplied SQL filters product and platform only in app.trial_events; no internal or test account exclusion appears.

Impact: If internal/test users exist in the source tables, they remain in the implemented denominator and may affect the rate. Direction and size are unknown.

S1S3

Refunded charges

Described

README says paying means a net-paid first charge and refunded charges do not count.

Implemented

The supplied SQL joins billing.charges with amount_usd > 0 and does not show refund or net-payment logic.

Impact: Refunded positive charges could be counted as conversions. Direction would overstate net-paid conversion if refunds are present; size is unknown.

S1S3

February comparison and onboarding claim

Described

Readout says 14.3% is up from 12.9% for February and that new onboarding is driving a 1.4-point lift.

Implemented

The supplied SQL and CSV contain only the March cohort summary and no February cohort, experiment assignment, adjustment, or causal design.

Impact: The supplied evidence supports the March descriptive rate, not the lift estimate or the onboarding causal claim.
